## M-001. AI-скаут — лидогенератор во фриланс-чатах

**Статус:** этап 1 готов — listener, SQLite, конфиг, логирование
**Архитектура:** [`docs/ai-scout/ARCHITECTURE.md`](docs/ai-scout/ARCHITECTURE.md)

Прогресс:
- [x] Этап 1: скелет, `.env`, SQLite, Telethon-listener с логом сообщений
- [x] Mock-replay: `MessageHandler` + fake-события + фикстуры (тест без Telegram)
- [ ] Этап 2: очередь и воркеры
- [ ] Этап 3: белый список / стоп-слова
- [ ] Этап 4: Claude (сложность + черновик)
- [ ] Этап 5: карточки в закрытый чат через бота

### Цель
В реальном времени читать сообщения в профильных Telegram-чатах, дешёво отсеивать мусор
по ключевым словам, отправлять оставшееся в Claude на оценку сложности и генерацию
черновика отклика, а затем присылать готовую карточку лида в наш закрытый чат.

### Ценность
- Не сидим в чатах руками: лид приходит с вердиктом и почти готовым ответом.
- Экономим токены: в LLM уходит только то, что прошло белый список и не попало в стоп-слова.
- Полуавтомат: отклик отправляет человек, а не бот — меньше риска бана и «спамных» ошибок.

### Объём MVP
1. Telethon-клиент слушает список чатов в реальном времени.
2. Фильтр по белому списку фраз + стоп-словам (конфиг в YAML).
3. Вызов Claude со структурированным JSON-ответом: сложность 1–5, вердикт, черновик отклика.
4. Бот (aiogram) отправляет карточку в закрытый чат: текст заказа, вердикт ИИ, черновик, ссылка на сообщение/клиента.
5. SQLite: дедупликация и история лидов.

### Вне scope MVP
- Автоматическая отправка откликов клиенту.
- Веб-админка и аналитика.
- Мультиаккаунтность и горизонтальное масштабирование.
- Голосовые/видео/файлы — обрабатываем только текст.

### Критерии приёмки
- [ ] Новое сообщение в тестовом чате доходит до карточки в закрытом чате < 60 сек.
- [ ] Сообщение без слов из белого списка не вызывает запрос к Claude (проверяется логом/счётчиком).
- [ ] Сообщение со стоп-словом («1С», «Битрикс», «за отзыв») отбрасывается.
- [ ] Повторная доставка того же сообщения не создаёт вторую карточку (дедуп по `chat_id:message_id`).
- [ ] Ответ Claude валидируется по схеме; при ошибке/таймауте лид помечается `failed`, пайплайн не падает.
- [ ] FloodWait и 429 обрабатываются с backoff, процесс переживает перезапуск.
- [ ] Секреты (api_id/hash, токен бота, ключ Anthropic) не попадают в репозиторий.

### Риски и как снижаем
| Риск | Снижение |
|------|----------|
| Бан аккаунта за парсинг/флуд | Только чтение, без массовых действий, лимиты, Human-in-the-loop |
| Дорогие вызовы LLM | Жёсткий префильтр, лимит длины, дневной бюджет, кэш системного промпта |
| Ложные срабатывания фильтра | Нормализация текста, границы слов, тесты на фикстурах, ручная правка списков |
| Галлюцинации в черновике | Черновик — только предложение, отправляет человек |
| Потеря сообщений при падении | Персистентная очередь/статусы в SQLite, идемпотентная обработка |

### Зависимости
- `TELEGRAM_API_ID`, `TELEGRAM_API_HASH`, сессия Telethon (одноразовый логин).
- Токен бота и ID закрытого чата.
- `ANTHROPIC_API_KEY`.
- Доступ к исходным чатам (аккаунт уже состоит в них).
